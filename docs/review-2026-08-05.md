Two independent read-only reviews of the repo at commit `cb9af26` (Phase 1 complete,

one on the UI (React idiomatics / re-render behaviour / readability).

Status key: `[ ]` open · `[x]` done · `[~]` deliberately deferred (with the reason).

## Bucket A — before Phase 2 closes (bugs + cheap high-impact fixes)

- [x] **A1. `latest_score` update is not scoped by run.** `mock/engine.py:499` —
  `UPDATE run_cells SET latest_score = ? WHERE case_id = ?` overwrites the score on
  every other run's cell sharing that case. Real defect. Add `AND run_id = ?`; add a
  regression test judging two runs that share a case.
- [x] **A2. `/tasks/stream` is an unfiltered cross-tenant firehose.** `openapi.yaml:1183-1219`
  declares no parameters; `mock/engine.py:78-80` fans every event to every subscriber.
  A user with `view` on tree A receives judgments (incl. reasoning), spans, and task
  results from every tree. Tree permissions live in the path, and this path has no tree.
  Fix: required/optional subscription filters (`tree`, `run_id`, `task_id`) **and**
  server-side authorization of each emitted event against the caller's permission matrix.
  Contract change → pairs with C-bucket v0.4.0, but the mock-side authorization filter
  should not wait.
  **Done (P2-FIXA): server-side authorization only.** Every broker event now carries the
  tree it belongs to (task/progress via the task's tree/run/turn, span via the turn's
  `tree_id`, judgment via run/turn) and each subscriber receives only events for trees
  their permission matrix grants `view` on; events whose tree cannot be resolved (judging
  standalone eval cases, which are tree-less by design) are withheld from limited callers
  rather than broadcast. **Still open:** the SUBSCRIPTION FILTERS (`tree`, `run_id`,
  `task_id` parameters on `GET /tasks/stream`) are a contract change and remain part of
  the C-bucket v0.4.0 work — `openapi.yaml` is untouched.
- [x] **A3. `/spans/{spanId}/payload` is globally addressable with no ownership check.**
  `openapi.yaml:1129-1150`, `mock/main.py:1148-1154`. Holds full prompts/responses.
  Verify the span's turn belongs to a tree the caller can view.
- [x] **A4. Markdown is re-parsed on every render.** `src/lib/markdown.tsx:11-16` runs
  `marked()` + `DOMPurify.sanitize()` unconditionally. During SSE streaming this is
  ~100–500 ms of main-thread work per second on a 30-turn conversation, and it also
  drives A6. Fix: `React.memo` the component + `useMemo` the sanitize on `[content]`.
  ~5 lines; highest impact-to-risk ratio in the codebase.
- [x] **A5. `chatSettings` in `AppContext` re-renders the whole app per keystroke.**
  `App.tsx:89`, `:202-203`, `AppContext.tsx:32-33`. Only `ChatPage` reads it. Move it to
  local `ChatPage` state (the instance survives `/chat` ↔ `/chat/:id`, so session-scope
  still holds).
- [x] **A6. Live-filling grid rebuilds every cell every 300 ms.** `RunDetailPage.tsx:239`
  refetches the whole `Run`; `ComparisonView.tsx:36` (`CellContent`) is unmemoized and the
  render props at `RunDetailPage.tsx:429,:440` are inline arrows. 360 cells × markdown ≈
  50–180 ms blocking, ~3×/s. Fix: `memo(CellContent)` + `useCallback` the render props.
- [x] **A7. Object-URL leak.** `ChatPage.tsx:185` unmount cleanup aborts the stream but does
  not revoke image-preview object URLs (revoked on remove/clear/switch only). One line.
- [x] **A8. Streaming draft should own its state.** Extract `ChatPage.tsx:103,:335,:482-490`
  into a `<StreamingBubble>` so a token re-renders one bubble instead of the page.
  (With A4 this makes token cost O(1) instead of O(turns).)

## Bucket C — contract v0.4.0 (expensive to retrofit; not urgent)

- [ ] **C1. Uniform, cursor-paginated collections.** One `Page<T>` envelope everywhere
  (judgments `openapi.yaml:1605-1618` and tasks `:1178-1181` return bare arrays; runs,
  casebooks, rubrics, sets, agents, users are unpaginated). Keyset cursors replace
  `page`/`page_size` on append-only stores — `OFFSET 200000` is O(offset) and pages shift
  under the reader.
- [ ] **C2. Conversation listings must not inline turns.** `openapi.yaml:2310-2313`, `:666`
  — ~400 KB/page at default, 2 MB at max, for a sidebar. `?include=turns` /
  `?turn_preview=N` + ETag.
- [ ] **C3. Run grid: pagination + ETag + cell-level fetch.** `openapi.yaml:2609-2679`
  returns every row × column with full content (~2.4 MB at 200×6).
- [ ] **C4. `PUT` used for non-idempotent appends.** `…/instructions` (`:563-588`),
  `/eval/rubrics/{id}` (`:1313`), `/eval/cases/{id}` (`:1455`), `/eval/sets/{id}` (`:1524`)
  all return 201-new-version. A retry after a socket timeout creates two versions.
  → `POST …/versions` + `Location`.
- [ ] **C5. Make the audit trail readable.** No `GET /eval/rubrics/{id}`, no `?version=`,
  no snapshot GET — yet `Judgment.rubric_version` (`:2947`) and `JudgeRequest.set_version`
  (`:2915-2918`) pin versions no endpoint can retrieve. Add GET + `?version=` +
  `…/versions` listings. Also missing: `GET /eval/cases` (POST-only at `:1340`).
- [ ] **C6. `Idempotency-Key` on every 202 endpoint** (`/replay`, `/eval/judge`,
  `/casebooks/{id}/replay`, `/eval/cases/import`) and pin down `client_message_id`'s scope,
  TTL, and same-key-different-body behaviour (`:2336-2343`; mock keys only on
  `(cmid, tree)` with no uniqueness constraint).
- [ ] **C7. SSE event ids + `Last-Event-ID` resume.** No ids emitted (`mock/util.py` `sse()`),
  so any proxy hiccup silently drops task completions and scores.
- [ ] **C8. Per-operation permission semantics.** `view/tune/evaluate` exist but no operation
  says which it needs; 403 is declared only on `/admin/*`. Add `x-required-permission` and
  declare 403 on tree-scoped writes.
- [ ] **C9. `Error` needs `details[]` + `request_id`; declare 422/429/503 globally.**
  422 appears once in the contract but the mock returns it from a dozen places.
- [ ] **C10. Batch turn fetch** (`GET /agenttrees/{tree}/turns?ids=`) — casebook rendering is
  currently N full-transcript requests (`openapi.yaml:1690-1691`).
- [ ] **C11. `Health.contract_version` + `capabilities[]`, and a `/v1` prefix** while it is
  still free (`:73`). Enum-widening is additive for clients but breaking for servers.
- [ ] **C12. Soft-delete must be visible.** `Conversation` has no `deleted` field and
  `Lineage` no `parent_deleted`, yet `:765-766` promises the UI renders a deleted parent.
- [ ] **C13. Search is unbounded `LIKE` over turn content** (`:675-677`; mock at
  `main.py:730-734`). Specify index-backed, best-effort, minimum length, estimated total.
- [ ] **C14. Span retention/TTL policy** — nothing in the contract says payloads expire;
  document 404-after-expiry on `/spans/{id}/payload`.
- [ ] **C15. Close the mock's implementation gap** — 25 of 69 operations still unimplemented
  (casebooks, memory, settings, eval sets/cases/import). A reference mock that doesn't serve
  its own contract lets divergent backend interpretations ship unnoticed. (Phase-2 tasks
  P2-T12/T12a/GEN/MEM close most of this.)

## Bucket D — persistence guidance for real backends (documentation task)

- [ ] **D1. Write `docs/persistence.md`** capturing the reviewed recommendation: Postgres
  spine (turns + judgments partitioned by month, keyset indexes, `judgment_latest` upsert
  table, precomputed run summaries); object storage for span payloads and attachments;
  ClickHouse/OTLP for span metadata with TTL; a durable workflow engine (Temporal-class) for
  the task engine — parent/child fan-out with partial failure, retry-failed and
  cancel-cascade is a workflow problem, not a job-queue problem; Redis for SSE fan-out
  (topics per tree/run/task) plus idempotency keys.
- [ ] **D2. Add a "do not copy the physical layer" header to `mock/db.py`.** Good shape
  reference (ADK-aligned `invocation_id` grouping, append-only via composite PKs, per-turn
  envelope, soft delete). Bad physical reference: **zero indexes**, `ORDER BY rowid` ~10
  places (SQLite-only), `lineage` as JSON queried with `json_extract` on hot paths,
  `attachments.data BLOB` in-row, span payloads inline (contradicting our own `payload_ref`
  design), **no transactions** (a replay enqueue is dozens of separate commits — crash
  mid-way leaves a half-built run), a process-wide `RLock` serializing all access, and
  **no tenant/owner column anywhere** even though `AdminConversationItem.user_id` is required.
- [ ] **D3. Add the tenant/owner column to the reference schema now.** Retrofitting ownership
  late is the most painful migration there is.

## What the reviews said was good (keep these)

- Tree-scoping stated once and actually held; unpermitted → 404, not 403.
- Append-only expressed structurally (composite PKs, no update/delete endpoints), with
  delete-as-tombstone naming exactly what survives.
- `payload_ref` indirection on spans — the best scaling decision in the contract.
- The context envelope: captured not reconstructed, stamped on inbound turns, frozen replay
  by default, per-cell `envelope_source` audit, explicit fallback policy.
- One chat endpoint with streaming as a body flag; `x-sse-events` documenting SSE shapes.
- `QueueProvider` correctly memoized — task frames re-render two leaves, not the shell.
- `src/api/sse.ts` and `src/api/target.ts` are exemplary (the latter is the only correct
  `useSyncExternalStore` snapshot handling in the repo).
- Zero `any`, zero `@ts-ignore`; casts confined to the client boundary.
- Tests are the strongest consistency story: every file opens by quoting the contract lines
  it defends; injectable timings and SSE gates instead of fake timers.
